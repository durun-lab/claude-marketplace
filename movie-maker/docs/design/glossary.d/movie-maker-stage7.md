## 構造と開発

| 用語 | 定義 | 識別子 |
|---|---|---|
| 本線（自動の改善の） | 回を取り込む専用のブランチ。人の main のチェックアウトの未コミットの変更を巻き込まない。PR の向き先（upstream）とは別 | `ImproveConfig::mainline`、`local/movie-maker` |
| 返事 | 回が要望ごとに書く、何をしたか（直さないならその理由）と結末 | `Reply` |
| 結末 | 回と要望の終わり方（取り込んだ、変更なし、PR 止め、差し戻し、失敗、人が止めた） | `RunOutcome`、`Outcome` |
| 差し戻し | 囲いの検査に通らなかった回の要望を未対応に戻し、理由を返事に書くこと。回のブランチは残す | `RunOutcome::Rejected`、`Outcome::Rejected` |
| 完了のマーカー | 回の最後の発言で、対応を終えた要望の並びの前に置く行（「対応した要望:」） | `DONE_MARK` |
| 区切り（回の） | Stop フックで `claude -p` のターンの終わりを取り、回を検査へ進めること | `STOP_FILE`、`run_settings` |
| 使用制限 | Claude の利用の上限。止まった回は区切らず、明ける時刻の 1 分後に同じセッションで続ける | `AgentEnd::UsageLimit`、`usage_limit` |
| 回の予算 | 1 つの回で `claude -p` に使ってよい費用と時間。回を起こしたときの値を回の状態にコピーし、続きの呼び出しには残りだけを渡す。計装の予算とは別 | `RunState::budget_usd`、`wall_ms`、`spent_usd` |
| すぐ止める | 自動の改善を OFF にし、動いている `claude -p` を木ごと止めて回を終える操作 | `Improver::stop` |
| 基準（回の） | 回の前に取る性能の結果と書き出しのハッシュ | `Baseline` |
| 起動の契機 | 回を起こすかを確かめるきっかけ（要望の保存、設定の変更、アプリの起動） | `Improver::kick` |
| バックグラウンドの実行（自動の改善の） | アプリで、起動の契機ごとに回を回すスレッド | `Improver::with_background` |
| 回のロック | 回を 1 つに限る OS のファイルのロック。アプリと `mm improve` が共有する | `RunLock`、`run.lock` |
| 疑いのある回 | 取り込みの直後に初めて起きたエラーと遅い処理に結びつけた回 | `ErrorRecord::suspect_run` |
| 出どころ（自動の起票の） | エラーと遅い処理が起きた所（アプリ、CLI、画面、ホスト） | `ErrorSource` |
| 指した部品 | Feedback パネルで人が要望に添えた画面の要素（セレクター、パネル、位置、スクリーンショット） | `FeedbackItem::targets`、`pick.ts` |
| Feedback のサービス | アプリで `Improver` を 1 つ持ち、IPC のハンドラー、panic のフック、計装の見張りが共有するもの | `win::feedback::Feedback`、`feedback::service` |
| 計装の見張り | 予算を超えたスパンとホストのクラッシュのカウンタを自動の起票に回す `Layer` | `feedback::watch::Watch` |
| ホストのクラッシュのカウンタ | 別プロセスのホストがクラッシュした回数のカウンタ（`<ホストの種類>.crash`）。ホストとの接続が数え、アプリが読む | `mm_trace::names::host_crash_counter` |
| 参照を動かすコマンド | 回の `claude -p` に拒否させる git と gh のコマンド。回のブランチ以外を動かすと囲いを通らずに取り込まれるため | `DENIED_COMMANDS` |
| ホットパッチ | 動いているアプリの Rust の関数を、起動し直さずに差し替えること。開発のときだけ（Dioxus の subsecond） | feature `hotpatch` |
| ホットパッチの呼び出し箇所 | ここで呼んだ関数だけが、パッチを適用した後に新しい関数に入る | `hotpatch::call` |
