# RFC: 素材のファイルの書き換えと、開く前の素材のデコーダーをフレームのキャッシュのキーに入れる

状態: 提案

## 変える理由

段階 8 を締めるレビュー（#150）の「残したもの」の 2 つは、どちらも前の画素を返す正しさの誤り。

- 素材のファイルを自分で読む種類（`shader.hlsl`、`lottie`、`color.lut`）は、取り込んだ後にファイルを書き換えても、キーに入る `contentHash` が取り込み時の値のままで、前の画素を返す。
- 入れ子とシーケンスのキーは、まだ開いていない素材のデコーダーをファクトリーの名前（`auto`）で表す。デコーダーの画素の作り方のバージョン（`ffmpeg+wide.1` など）が上がっても、前のビルドのディスクの退避に当たる。

## 足したもの（形は変えない）

| 型 | 足したもの | 既定 |
|---|---|---|
| `mm_node_api` | `fn file_digest(path: &Path) -> Option<String>`。ファイルの中身のハッシュ。大きさと更新時刻が前と同じなら読み直さない。更新から 2 秒以内のファイルはハッシュをキャッシュしない | |
| `mm_node_api` | `fn file_stamp(path: &Path) -> String`。ファイルの大きさと更新時刻のスタンプ。無いファイルは `absent` | |
| `mm_decode_api::DecoderFactory` | `fn backend_ids(&self) -> Vec<&'static str>`。開いたデコーダーが `Decoder::backend_id` で名乗りうる名前の全部 | `[id()]` |

契約に書き足したもの:

- `Decoder::backend_id` で名乗る名前を足した実装は、`backend_ids` にも足す。`ffmpeg`、`d3d12va`、`cuvid` は名乗る名前を定数に置き、両方から引く。`auto` は試す実装とフォールバックの名前の和を返す。
- レンダラーは、まだ開いていない素材のデコーダーを `<ファクトリーの名前>[<backend_ids をカンマでつないだもの>]` としてキーに入れる。

## 振る舞いが変わる所

- `shader.hlsl`、`lottie`、`color.lut` は素材のファイルの中身のハッシュを種類の指紋に入れる。`shader.hlsl` は DXC のバージョンも入れる。素材のファイルを読めなければ指紋は `None` で、キャッシュしない。
- `web.cef`（ホストあり）は、ホストの実行ファイルと `CEF_PATH` の `libcef.dll` のスタンプを種類の指紋に入れる。
- この 4 つの種類の画像と、それを含む入れ子の画像は、前のキーに当たらず 1 回描き直す。
- 開く前の素材に頼る入れ子とシーケンスの画像は、前のキーに当たらず 1 回描き直す。

## 先行事例

| 先行事例 | 採ったもの |
|---|---|
| Bazel と Nix（入力の中身のハッシュで結果を引く） | 素材のファイルは今の中身のハッシュで表す。プロジェクトをコピーして更新時刻が変わっても当たる |
| git の index（大きさと更新時刻が同じならハッシュし直さない。racy git） | ハッシュを大きさと更新時刻でキャッシュし、更新の直後のファイルはキャッシュしない |
| Nuke の Read のハッシュ（ファイルの更新時刻を入れる）、OpenFX の HostSupport（バンドルの更新時刻で describe を無効にする） | 数百 MB の実行ファイルと共有ライブラリは大きさと更新時刻で表す |
| Nuke と Houdini のキャッシュのハッシュ（ノードの外の入力も入れる） | 開く前に決まらないデコーダーは、選びうる全部の名前を入れる |

## 比べて選ばなかった形

- 開く前の素材のデコーダーを、取り込み時の情報（ビット深度など）から決める: `auto` は素材ごとに GPU の実装を試して選ぶので、開くまで決まらない。プロジェクトのデータにビット深度も無い。
- 前の起動で選んだ実装を覚えて使う: 覚えた名前は前のビルドのバージョンなので、それだけではバージョンの上がりを拾えない。選びうる名前の組と突き合わせる必要があり、組だけで足りる。
- 開くまでキャッシュしない: シーケンスの中のまだ開いていないカットの素材のせいで、シーケンスの画像をほとんどキャッシュできない。
- 素材の全部（撮影素材も）を種類の指紋ではなくレンダラーで調べる: 撮影素材のデコーダーの索引も `contentHash` で引くので、キーだけを変えても正しくならない。取り込み直しで扱う（残したもの）。

## 使う所

- `mm-nodes-hlsl`、`mm-nodes-lottie`、`mm-nodes-basic`（`color.lut`）、`mm-nodes-cef` の `cache_fingerprint`。
- `mm-render` の `frame_cache::unopened_decoder`。
- `mm-runtime` の `Engine::decoder_backend_ids`。配信の区間のキー（`mm-stream`）が `decode=auto` の代わりに入れる。区間のキーは種類の指紋を入れているので、素材のファイルの書き換えは変更なしで拾う。

## 残したもの

- 撮影素材と画像を同じパスで上書きしたとき: `contentHash` もデコーダーの索引も古いまま。ファイルの変化を見て取り込み直す仕組みが要る。
- `text` が使う OS の書体: 書体の組は文字の実装（`TextShaper`）が起動時に読むので、種類の指紋では表せない。文字の実装に書体の組の指紋を出させる。
- プロジェクトの書体の素材のファイルの書き換え: CEF のホストは `contentHash` の名前で書体をコピーするので、キーだけを変えても正しくならない。
