# RFC 0132: パラメータの組で変わるノードの種類のパラメータの一覧

状態: 提案

## 変える理由

段階 8 の `ofx`（`mm-nodes-ofx`）は、パラメータ `bundle` と `plugin` で選んだ OpenFX の効果のパラメータ（describe の結果）を、種類のパラメータとして出す。`NodeKind::params()` は引数を取らず種類ごとに 1 つの一覧しか返せないので、選んだ効果の分を UI の入力フィールドと MCP の引数に出せない。

## 足したもの（形は変えない）

| 型 | 足したもの | 既定 |
|---|---|---|
| `mm_node_api::NodeKind` | `fn params_for(&self, params: &Params) -> ParamSchema`。そのパラメータの組のときの一覧。パラメータで一覧が変わる種類が上書きし、`params()` の後ろに選んだものの分を足して返す | `params()` を返す |

契約に書き足したもの:

- `params_for` の先頭は `params()` と同じ並び。足す分は `params()` と同じ名前を持たない。
- `params_for` は重い準備（別プロセスの起動）をしてよいが、結果を覚えて 2 回目からは速く返す（`ofx` は describe の結果をバンドルごとに覚える）。

## 振る舞いが変わる所

無い。既存の種類は既定の実装のまま。レンダラーは今までどおり `params()` の既定値で埋め、`params()` に無い名前の値もそのまま種類に渡す（`ofx` はそれをプラグインに渡す）。

## 先行事例

| 先行事例 | 採ったもの |
|---|---|
| OpenFX（インスタンスごとにパラメータの記述子を describe で受ける） | 一覧を種類ではなくパラメータの組（どのプラグインか）で決める |
| VST3 と CLAP のホスト（プラグインを読み込んでからパラメータの一覧を引く） | 選ぶ前は自前のパラメータだけ、選んだ後は足した一覧 |

## 使う所

- `mm-nodes-ofx` の `OfxKind`: `bundle`（と `plugin`）が指す効果の `ParamSchema`（隠しのもの、値を持たないものを除く）を足す。
- 段階 8 の CLAP と VST3 の種類も同じ形で使える。
- UI の入力フィールドと MCP の引数を作る側は、`params()` の代わりに `params_for(ノードの今の値)` を引く（各担当が移す）。
