# RFC 0132: パラメータの組で変わるパラメータの一覧、種類の指紋、ホストとの共有メモリ

状態: 提案

## 変える理由

段階 8 の `ofx`（`mm-nodes-ofx`）で、今のインターフェースでは 3 つのことができない。

- 選んだ効果のパラメータを出す。`ofx` はパラメータ `bundle` と `plugin` で選んだ OpenFX の効果のパラメータ（describe の結果）を、種類のパラメータとして出す。`NodeKind::params()` は引数を取らず種類ごとに 1 つの一覧しか返せないので、選んだ効果の分を UI の入力フィールドと MCP の引数に出せない。
- プラグインの差し替えをキャッシュのキーに出す。フレームのキャッシュのキーはパラメータと素材の `contentHash` から作るので、プラグインの共有ライブラリを差し替えても同じキーになり、前の画素を返す（正しさの誤り）。
- 画像を速く渡す。ホストとの画像の受け渡しを JSON の数の配列で行うと、1080p の往復に release で 1.6 s かかる。

## 足したもの（形は変えない）

| 型 | 足したもの | 既定 |
|---|---|---|
| `mm_node_api::NodeKind` | `fn params_for(&self, params: &Params) -> ParamSchema`。そのパラメータの組のときの一覧。パラメータで一覧が変わる種類が上書きし、`params()` の後ろに選んだものの分を足して返す | `params()` を返す |
| `mm_node_api::NodeKind` | `fn cache_fingerprint(&self, params: &Params, asset_path: &dyn Fn(&AssetId) -> Option<PathBuf>) -> Option<String>`。画素を変えうる、パラメータと素材の外の入力の指紋。`None` ならそのフレームをキャッシュしない | 空の文字列 |
| `mm_host_pipe::shm`（共通実装） | 名前つきの共有メモリ `Mapping`（大きさを指定して作る・開く、バイト列と型つきの借用）、自動で戻る `Event`、終わりを待てる `Process`、`unique_link`、`object_names`、f32 の配列の読み書き。`mm-host-clap` にあったものを移し、`mm-host-ofx` と共有する | |

契約に書き足したもの:

- `params_for` の先頭は `params()` と同じ並び。足す分は `params()` と同じ名前を持たない。
- `params_for` と `cache_fingerprint` は重い準備（別プロセスの起動）をしてよいが、結果をキャッシュして 2 回目からは速く返す（`ofx` は describe の結果をバンドルごとにキャッシュする）。
- レンダラーは、レイヤーの種類の指紋をレイヤーの画像のキーに、入れ子の中の種類と効果の指紋を入れ子の画像のキーに入れる。空の指紋はキーを変えない（既存のキャッシュはそのまま当たる）。

依存の規則（14-dev-structure の規則 3）に書き足したもの:

- ホストに画像を渡す種類（`mm-nodes-ofx`）も `mm-host-pipe` に依存してよい。共有メモリはアプリの側（種類）が作り、ホストが開くので、両方が同じ実装を使う。`mm-nodes-cef` の共有テクスチャのように種類の中で OS の呼び出しを書き直すより、1 か所に置く。

ホストとアプリの間のプロトコル（`mm-host-api` のインターフェースは変えない）:

- `mm-host-ofx` の `RenderParams` に `shared: { name, has_source }` を足した。入力と結果は共有メモリの `[入力 | 結果]` に RGBA f32（リトルエンディアン、上の行から）で置き、結果を共有メモリに書いた応答は `SharedFrame::Cpu` の `data` を空にする。共有メモリを作れない環境では今までどおり JSON で渡す。

## 振る舞いが変わる所

- `ofx` のレイヤーと、`ofx` を含む入れ子は、プラグインを差し替えると描き直す。
- ほかの種類は既定の実装のままで、キャッシュのキーも変わらない。

## 先行事例

| 先行事例 | 採ったもの |
|---|---|
| OpenFX（インスタンスごとにパラメータの記述子を describe で受ける） | 一覧を種類ではなくパラメータの組（どのプラグインか）で決める |
| VST3 と CLAP のホスト（プラグインを読み込んでからパラメータの一覧を引く） | 選ぶ前は自前のパラメータだけ、選んだ後は足した一覧 |
| OpenFX の HostSupport（describe の結果をバンドルの更新時刻で無効にする）、Nuke のキャッシュのハッシュ（ノードの外の入力も入れる） | プラグインのスタンプをキャッシュのキーに入れる |
| `mm-host-clap`（#133。音のブロックを名前つきの共有メモリとイベントで往復させる） | 同じ実装を共通にし、画像の受け渡しに使う |

## 使う所

- `mm-nodes-ofx` の `OfxKind`: `params_for` で効果の `ParamSchema` を足し、`cache_fingerprint` でバンドルの実体のパス、中身のスタンプ、効果の識別子を返す。画像は `mm_host_pipe::shm` で渡す（1080p の往復は release で p50 26 ms）。
- `mm-render` の `frame_cache/key.rs`: 指紋をキーに入れる。
- `mm-host-clap`: 区画の中の並び（`Block`）だけを持ち、区画とイベントは `mm_host_pipe::shm` を使う。
- 段階 8 の VST3 の種類も同じ形で使える。
- UI の入力フィールドと MCP の引数を作る側は、`params()` の代わりに `params_for(ノードの今の値)` を引く（各担当が移す）。
