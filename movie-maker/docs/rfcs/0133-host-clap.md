# RFC 0133: CLAP のホストと、レイヤーの音の効果（mm-host-clap）

状態: 提案

## 変える理由

- 段階 8 の CLAP（07-standards の「VST3、CLAP」の行）を、レイヤーの音に挿せる効果として使えるようにする。
- ノードのインターフェースの音は `render_audio`（音を出す）だけで、入力の音を受けて変える口が無い。
- `mm-host-api` のプロトコルは画像（`RenderFrame` → `Frame`）の形で、音のブロックを運ぶ要求が無い。

## 決めたこと

### ノードのインターフェース（`mm-node-api`）に足すもの

足すだけで、既定の実装があるので今の種類とレンダラーはそのまま動く。

| 足すもの | 内容 |
|---|---|
| `AudioEffectCx` | 区間（コンポジションの時間軸）、インスタンスのキー（コンポジション、レイヤー、効果の ID）、区間の中のパラメータの列（区間の先頭からの位置、評価済みの値）、サンプルレート、チャンネル数 |
| `AUDIO_PARAM_STEP`（64） | パラメータを評価する格子の間隔（フレーム）。コンポジションの時間軸の 0 から数える |
| `NodeKind::process_audio(&self, cx, block)` | 音の効果として `block` をその場で変える。既定は何もしない |

- レンダラー（`mm-render` の `audio_effects.rs`）は、レイヤーの `effects` のうち `traits().audio` が真の種類を、レイヤーの音（音量、パン、フェードの前）に上から順にかける。DAW のトラックのインサート（フェーダーの前）と同じ位置。
- パラメータを区間の先頭だけで評価すると、区間の分け方で値の変わる位置が動き、書き出しと再生の音がずれる。格子で評価すれば、分け方に依らず同じ位置で変わる。区間の先頭の点は、その前の格子の時刻で評価する。
- 効果が失敗したら、その効果をかけずに続け、レンダラーのエラーに残す（ほかのレイヤーの音は止めない）。

### プロジェクトのデータ

変えない。効果は今の `Layer.effects`（ID つきのノード）に種類 `audio.clap` のノードとして置き、プラグインのパラメータはノードのパラメータ `param.<CLAP のパラメータの id>` に持つ。ノードのパラメータは今のままキーフレームを打てる。

### ホストのプロトコル（`mm-host-api`）

変えない。制御（`Ping`、`Prepare`、`Shutdown`）だけを今のプロトコルで送り、音のブロックとパラメータのイベントは、アプリが作る名前つきの共有メモリと 2 つのイベント（要求、完了）で往復させる（06-engine の「共有メモリで音を往復させる」）。`RenderFrame` には `Error` を返す。

### クレート

| クレート | 依存 | 内容 |
|---|---|---|
| `mm-host-clap` | `mm-audio-api`、`mm-host-api`、`mm-node-api`、`mm-types`、`mm-host-pipe`、`clack-host`、`clack-extensions` | ホストの実行ファイル（`serve`、`describe`）、アプリ側の `ClapEffect`、種類 `audio.clap`（`ClapEffectKind`） |

- 依存の規則 3 の「別プロセスのホストは `mm-host-pipe` に依存してよい」に `mm-host-clap` を並べる（14-dev-structure の更新は統合の担当）。
- 07-standards は VST3 と CLAP を 1 つの `mm-host-audio` に置く案だった。段階 8 の「全部が別の実装のクレート。互いに独立」に合わせ、CLAP を先に `mm-host-clap` にした。VST3 は SDK が別に要り、作る条件が違う。共有メモリの受け渡し（`shm.rs`）は VST3 を足すときに共通実装へ移す（RFC 0120 と同じ手順）。
- `mm-runtime` は wgpu のレンダラーのレジストリに `audio.clap` を組み立てごとに 1 つ登録する。インスタンスの状態（プラグインの遅延の中身など）を組み立て（レンダラー）ごとに分けるため、`web.cef` のようにプロセスで共有しない。ホストの実行ファイルは `MM_CLAP_HOST` か、実行ファイルと同じフォルダーの `mm-host-clap` を使う。

## 影響

- API クレートの変更は `mm-node-api` に足すだけ。既存の種類とレンダラーの呼び出しは変わらない。
- `mm-render` の音の経路に効果の呼び出しが入る。`traits().audio` が真の種類を `effects` に置かなければ、今までと同じ音。
- `mm-runtime` の wgpu のレジストリの種類が 1 つ増える（`assemble_real` の数を直した）。
