# RFC export-stages: 書き出しの流れを描画の段と符号化の段に分ける

状態: 提案

## 変える理由

書き出しはレンダラーの `export_range` が区間を一息に描き、同じスレッドでエンコーダーに押していた。配信の区間の符号化もこの流れで、その間は描画のスレッドが `Engine` を保持するので、Claude の `GET /frame` と静止画のフレームは区間 1 本（約 0.3〜0.4 秒）を待った（段階 9 のレビュー、#158、#162）。符号化（libx264 で 1 フレーム約 1.4 ms、ProRes で約 27 ms）も描画と交互に進み、重ならなかった。

## 足したもの（形は変えない）

| 型 | 足したもの | 既定 |
|---|---|---|
| `mm_render_api::Renderer` | `fn export_frame(&mut self, req: &RenderRequest, nv12: bool) -> Result<Box<dyn PendingFrame>>`。書き出しの 1 フレームを描いてリードバックを出し、待たずに返す | `render_frame` で描き、その場でリードバックした RGBA |
| `mm_render_api` | `enum ExportFrame { Rgba(RgbaImage), Nv12(Nv12Frame) }`。符号化の段に渡す 1 フレーム | |
| `mm_render_api` | `trait PendingFrame: Send { fn finish(self: Box<Self>, gpu: &mut dyn GpuHelper) -> Result<ExportFrame>; }`。リードバックを待っているフレーム。`ExportFrame` は自分を返す | |

`export_range` は残す。wgpu の実装は `export_frame` を 3 枚先行させて押す形にし、NV12 を受けないエンコーダーにも RGBA のリードバックを先行させる。

## 振る舞いが変わる所

- `mm-export` は 1 つのレンダラーで描くとき、描画の段（`Engine` を持つ。`export_frame` をリードバック 3 枚先行で呼ぶ）と符号化の段（`Engine` を持たない別のスレッド）を長さ 4 の受け渡しのキューでつなぐ。満ちたら描画の段が待つ。押すフレームの中身と順は前と同じ。
- `mm_export::export_run_interleaved` は、描画の段がフレームを 1 つ渡すごとに `Engine` を呼び出し側に貸す。`mm-stream` の描画のスレッドはそこで急ぎの仕事（静止画のフレーム、`GET /frame`、キャッシュの破棄）を済ませる。区間の途中のキャッシュの破棄と別の時刻の描画は、区間の残りのフレームのデコードをやり直させる（シーク）ので遅くはなるが、描く中身は変わらない。
- 符号化の段の失敗は送信の失敗で描画の段に、描画の段の失敗と取り消しは終わりの印なしに閉じた受け渡しのキューで符号化の段に伝わり、先に止まった段のエラーを返す。
- 符号化の段は RGBA も 1 枚ずつ押す（スパン `export.encode` が 1 フレームに 1 回）。並行の描画は前と同じ。

## 測った結果

- 出力は前とビット単位で同じ（`perf-export` の libx264、2 パス、ProRes 422 HQ の書き出しのファイルの MD5 が一致）。
- 配信の 360p の 4 秒の区間を作る間に積んだ `Engine` を借りる仕事は、121 回とも区間の途中で動き、待ちは中央値 1.4 ms、最大 70 ms（前は区間の終わりまで待った）。
- 速さは変わらない（1080p60 の libx264 で前 267 fps、後 266 fps。ProRes は 22 fps と 21 fps）。符号化の段の libx264 と ProRes が CPU を使い切るので、描画の段と重ねても全体は縮まない。重ねて効くのは CPU の空く GPU のエンコーダー（NVENC）で、この PC は今ドライバーが古く NVENC が開けない（[計装の予算の表](../design/17-instrumentation.md#予算の表)）。

## 先行事例

| 先行事例 | 採ったもの |
|---|---|
| FFmpeg（フィルターグラフとエンコーダーを別のスレッドで回し、フレームのキューでつなぐ。`-threads` とは別の段の並行） | 描画と符号化を別のスレッドにし、間をフレームのキューにする |
| OBS（描画スレッドが GPU で色変換してステージングのテクスチャに写し、数フレーム遅れてマップし、符号化スレッドへキューで渡す） | GPU で NV12 にし、リードバックを数フレーム先行させ、マップした後のフレームだけを符号化の段に渡す |
| GStreamer の `queue` 要素（`max-size-buffers` で上限を決め、満ちたら上流を止める。下流の失敗は上流の `push` の戻り値で伝わる） | 受け渡しのキューの長さに上限を付けて背圧にし、相手の段の停止を送受信の失敗で知る |
